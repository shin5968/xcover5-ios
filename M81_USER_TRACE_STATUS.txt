Why
  M69 logs only SpringBoard/backboardd breakpoint registers, without user memory.
  M75 still lacks the logd readdir(NULL) caller, M78 shows SpringBoard alive but
  layers0, and M80 only samples process state. Upstream's trace adds, for any
  process: crash message text (x0-x3/x8/x16 strings left by assertion helpers),
  shared cache slide, frame-pointer return addresses, abort() call stacks and
  periodic per-thread stacks of a named process or a CPU share list ("top").

Hooks (same sites as upstream redwood.patch)
  osfmk/kern/exception.c exception_triage_thread: before existing triage.
  bsd/kern/kern_sig.c __pthread_kill(SIGABRT): after the target port and signal
  are validated, and only when the target is the calling thread (abort() itself).
  Upstream traced the sender before validation, so another-thread or invalid
  requests were reported as the sender aborting.
  osfmk/conf/files.arm64: standard source next to sleh.c.
  M69 breakpoint logger and every existing exception flow remain unchanged.

XCover5 changes from upstream (test_m81_usertrace.py checks this exact list)
  No Redwood loader log: loader_log_line removed; console printf only.
  userabort lines also need systrace, so a kernel built with 0096 but without
  the boot-args below prints nothing new.
  ustacks/top thread call at THREAD_CALL_PRIORITY_LOW instead of the default
  high priority, so on one core it does not preempt the processes it observes.
  Comments only otherwise.

Boot-args (none are in the current packaging cmdline)
  systrace=1                       usertrap: / userabort: lines
  ustacks=SpringBoard ustacks_at=60 ustacks_ms=10000 ustacks_count=6 ustacks_threads=1
                                   main-thread pc/lr/return addresses
  ustacks=top ustacks_at=60 ustacks_ms=10000 ustacks_count=6
                                   busy percentage and top 12 processes
  Optional ustacks_threads=N, ustacks_tname=TEXT (e.g. coreanimation).
  Addresses minus the printed slide resolve in the exact iOS16.5 dyld cache.
  Console volume: one logical line per thread, up to ~250 bytes (pc, lr and 14
  return addresses), which wraps over several rows of the 720px console; without
  ustacks_threads a report may cover up to 96 threads in each of 8 matching
  processes. Keep ustacks_threads=1 or ustacks_tname on the framebuffer console.
